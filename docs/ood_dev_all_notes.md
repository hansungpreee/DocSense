# 개발용 OOD 정리 (29종 체계 기준, 2026-11-02)

백엔드 1 요청: 소분류가 29종이 되어 OOD 라벨을 맞춘다. 합본은 `data/meta/ood_dev_all_labels.csv` (11종 × 10건 = 110행, `python src/eval/merge_ood_dev.py`).

## 합본 규칙
- 열: `file,major_code,major,minor_code,minor,split,nearest_minor_code`. labels.csv 열에 마지막 열만 더했다.
- `major_code`=ETC, `major`=기타, `minor_code`=OOD 종류(DEVOOD-xx), `minor`=문서 이름, `split`=ood.
- `nearest_minor_code`: tip 평가용. 닮은 소분류가 없으면 빈칸.
- DEVOOD-03 발주서(10장)는 SAL-04가 되어 뺐다. 이미지 파일은 지우지 않았고 라벨에만 없다.
  `render_ood.py --dev`가 난수를 이어 쓰므로 종류를 빼고 다시 만들면 DEVOOD-04~06 이미지가 달라지기 때문이다.
- ood_dev2(DEVOOD-07~12)는 내용 그대로다. 새 체계 기준으로도 6종 모두 체계 밖이다.

## 새 소분류와 닮은 종류 확인 (정의는 PR #76 `docs/taxonomy-add-6` 기준)
| 종류 | 결론 | 근거 한 줄 |
|---|---|---|
| 반품폐기확인서 (DEVOOD-09) | 체계 밖 유지 (가장 가까운 SAL-05) | 납품확인서(SAL-05)는 납품·발주번호와 납품처의 인수 확인이 핵심인데, 이 문서는 확인번호·사유·폐기/반송 처리 내역이라 인수가 아니다. 품목·수량 표와 확인자·입회자 서명란이 겹쳐 모델이 SAL-05로 확정할 위험이 있는 경계 사례다. |
| 택배운송장 (DEVOOD-12) | 체계 밖 유지 (가까운 소분류 없음) | 발송인·수취인·운임·배송 메모만 있고 발주번호·납품일·납품 수량이 없다. 발주서(SAL-04)·납품확인서(SAL-05) 정의의 필수 항목이 하나도 없다. |
| 부서별예산집행실적표 (DEVOOD-06) | 체계 밖 유지 (가장 가까운 MGT-01) | 연간사업계획서(MGT-02)는 다음 연도 목표·월별 계획·추진 과제 중심인데, 이 문서는 배정 예산 대비 지난 분기 집행액과 전년 동기 비교라 과거 실적이다. 전년 대비 비교표 모양은 MGT-01과 닮는다. |
| 비품구매요청서 (DEVOOD-02) | 체계 밖 유지 (가장 가까운 SAL-04), 요청 목록에 없던 추가 확인 | 품목·수량·단가·희망납기 표가 발주서와 닮았으나 공급처 정보·발주번호가 없고 사내 부서의 구매 요청이다. |
