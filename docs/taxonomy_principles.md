# 분류 체계 원칙과 경계 규칙

`config/taxonomy.yaml` 머리말 주석의 원칙 7개를 풀어 쓴 문서입니다. 소분류를 승인하거나 정의를 고칠 때 이 문서를 기준으로 삼습니다.

- 근거: ISO 15489-1:2016(KS X ISO 15489-1) 8.3절 업무분류체계, ISO/TR 26122(업무과정 분석). 민간에는 권고(자율 채택)이며, 어느 문서가 어느 기능인지는 조직이 정합니다.
- ISO의 단위업무(transaction) 단계는 이 프로젝트 범위 밖입니다. 우리 체계는 기능(대분류) → 활동 → 양식(소분류) 3단계입니다(10/29 회의 결정, 활동은 가안: [taxonomy_structure_1029.md](taxonomy_structure_1029.md), #77).
- 조사 문서: [사내 문서 분류 체계 가이드라인 조사](https://claude.ai/artifact/A2zwuWeV4U1gUWGnA6hEa7) (2026-10-26)
- 상태: **제안 (10/29 회의 결정 반영, 병합 전 `taxonomy.yaml` 변경 없음)**

## 원칙

1. 대분류는 HS리테일의 업무 기능이다. "이 문서는 어느 업무를 하려고 만들었나"로 정한다.
2. 소분류는 그 기능에서 생기는 문서 유형(양식)이다. 제목·표 구성 등 보이는 특징으로 구분한다.
3. 문서 형식(계약서·신고서·보고서)만으로 대분류를 정하지 않는다.
4. 한 문서 유형은 한 기능에만 둔다. 두 기능에 걸치면 아래 경계 규칙을 따른다.
5. 소분류 코드는 식별자다. 대분류를 옮겨도 코드를 다시 발급하지 않는다(라벨·파일명·과거 결과 비교 유지).
6. 소분류 정의(definition)에는 보이는 특징만 쓴다. 기능 설명은 `taxonomy.yaml` 주석과 이 문서에 둔다.
7. 소분류를 더하거나 옮길 때 확인: 어느 기능인가, 기존 소분류와 보이는 특징으로 구분되는가, 개발셋 혼동은 없는가. 소분류는 회의에서 정해 체계에 넣으며, 체계 밖 문서는 「기타」로 분류한다(10/29: 신규 분류 제안·승인 기능 삭제).

6번을 둔 이유: v2·v3 프롬프트는 정의를 그대로 넣습니다. 정의에 기능 문장을 더하면 프롬프트가 바뀌어 재측정이 필요하고, `docs/taxonomy_definition_check.md`가 지적한 대로 문서에 없는 낱말이 오분류를 만들 수 있습니다. 주석은 `format_taxonomy()`가 읽지 않으므로 이 문서와 주석을 고쳐도 프롬프트는 바뀌지 않습니다.

## 대분류가 맡는 업무 기능

| 대분류 | 맡는 업무 기능 |
| --- | --- |
| 인사/채용 | 채용, 근로계약, 직원에게 급여를 계산·안내·지급, 휴가 등 근태 |
| 재무/회계 | 장부·결산·재무제표, 세무서·공단 등 외부 기관 신고, 예산 집행 관리 |
| 경영/전략 | 경영 성과 분석과 의사결정 보고, 연간 계획 |
| 영업/제안 | 거래 건 단위의 실행: 견적, 발주, 방문, 영업 출장 |
| 고객/거래처 | 거래처·가맹점과의 관계 설정: 비밀유지·가맹 등 거래 조건 약정 |
| 법무/총무 | 회사 자산·시설·비품 관리와 그 계약(임대차, 비품 구매) |

감사보고서는 특정 대분류의 업무가 아니라 각 대분류가 자기 업무의 감사를 맡습니다(경계 규칙 3).

## 경계 규칙

1. **계약서는 계약 상대방과 하는 업무 기능을 따른다.** 직원은 인사(HR-02), 거래처·가맹점은 고객/거래처(CUS-01·02), 부동산·시설은 법무/총무(LEG-01·02).
2. **급여·신고 서류는 누구에게 내는지를 따른다.** 직원에게 급여를 알리는 문서는 인사(HR-03), 세무서·공단 제출용 신고·영수증은 재무(FIN-04~08).
3. **감사보고서는 감사 대상 업무를 따른다.** 감사 대상이 재무면 재무/회계, 인사·급여면 인사/채용, 재고·구매면 영업/제안, 가맹·계약이면 고객/거래처, 정보보안이면 법무/총무에 둔다(10/29 회의: 감사 대상별 분리, 구체 안은 #77·#79). 이 규칙으로 FIN-09 하나가 여러 소분류로 나뉘며, 기존 코드 FIN-09는 재무 감사에 유지한다(원칙 5). 분리 전까지 `taxonomy.yaml`은 바꾸지 않는다.
4. **구매는 무엇을 사는지를 따른다.** 회사가 쓰려고 사는 비품·시설은 법무/총무, 팔 상품의 주문·매입은 영업/제안.
5. **보고서는 다루는 업무 기능을 따른다.** 영업 출장 결과는 영업, 부서 예산 집행 실적은 재무, 거래처별 손익 분석은 경영(MGT-01).

규칙 4·5는 승격 예정 소분류(비품구매요청서, 발주서, 출장결과보고서, 부서별예산집행실적표)의 정의를 쓸 때 적용합니다. 부서별예산집행실적표를 재무로 둘지 경영으로 둘지는 표준이 정해 주지 않으므로 팀이 정합니다(가안: 재무).
