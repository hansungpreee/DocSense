# vFinal 예외 규칙 반복 개선 (11/16~, 백엔드 1)

vFinal 프롬프트에 dev 약점 사례에서 뽑은 **예외 규칙 5개**를 넣고 Qwen으로 고치고 다시 재는 과정을 반복한 기록이다.
test(`split=test`)는 열지 않는다. 프롬프트는 버전을 늘리지 않고 vFinal 한 곳에서 고친다(10/29 결정).
기준은 고치기 전 vFinal(커밋 `d795bb1`, 정의 수정 반영 100종 main `config/taxonomy.yaml`)의 Qwen `qwen3.7-plus-2026-05-26` 결과다.

## 규칙과 근거 사례

| 규칙 | 원칙 | 근거로 본 오답 (튜닝용) | 같은 유형, 규칙 만들 때 안 본 것 (확인용) |
|---|---|---|---|
| 1 | 표·칸 양식이 아니라 줄글·메모·옮겨 적은 글이어도 항목과 목적이 맞으면 그 소분류. 「서술형이다」는 「기타」 이유가 아님 | 줄글 HR-03_002 「내용을 설명하는 메모」, 다듬은 줄글 SAL-03_H2 「서술형 보고서」 외 3 | HR-03_012, SAL-03_H1, FIN-05_H2, FIN-06_H1, SAL-04_H2, SAL-05_H2, LEG-01_H1·H2 |
| 2 | 제목에 부제·겸용 표기·연도가 붙어도 그 소분류. 제안할 새 이름이 기존 이름을 포함하면 기존 소분류 | hard2 FIN-07_004 「사업소득 원천징수영수증 / 지급명세서」를 새 분류로 제안 (확신도 1.0) | hard2 FIN-07_005·024 (v2에서 같은 유형) |
| 3 | 당사자·금액·품목표·날짜 같은 공통 항목이 아니라 그 소분류만의 항목과 목적으로 가름 | 줄글 SAL-01_002 견적서 → 세금계산서 (공급자·세액 칸만 인용) | SAL-01_012, FIN-07_002·012 (Gemini가 FIN-08로) |
| 4 | 항목 몇 개가 닮아도 이름과 목적이 다른 별개의 업무 문서면 그 소분류가 아님 → 「기타」 | 개발용 OOD 출장결과보고서_001 → 거래처 방문일지, 고객사과문발송대장_001·002 → 클레임 처리 보고서 | 출장결과보고서_005·010, 고객사과문발송대장_005·010 |
| 5 | 구분 근거(제목·머리글·고유 항목)가 잘리거나 없으면 확신도를 기준값 미만으로 → 사람 확인 | hard2 상단 잘린 LEG-02_003, 줄글 빈 페이지 FIN-03_002·012 | LEG-02_013·023, FIN-02_002·004·012, FIN-03_004 |

- 묶음 정의: `sets.csv` (`weak` 열이 `tune:N`·`check:N`). 확인용 사례는 규칙 문장을 쓸 때 근거 문장을 기준으로 삼지 않은 문서다(같은 생성기에서 나온 문서라 완전한 새 데이터는 아님).
- 규칙 5는 정답을 맞히게 하는 규칙이 아니다. 이미지에 답이 없는 문서를 높은 확신도로 잘못 확정하지 않고 사람에게 넘기게 한다. 그래서 약점 표에서만 「사람 확인으로 넘김」을 성공으로 센다. 세트 정확도에서는 여전히 오답이다.
- FIN-06_H2는 라벨이 의심되는 문서(5번 문서 참조)라 약점 사례에서 뺐다. C 세트 회귀에는 그대로 있다.

## 측정 방법

- 매 반복: 회귀 표본 약 430장 = 약점 사례 36건 전부 + 줄글 B 123·다듬은 줄글 C 24 전부 + hard2 소분류마다 5장 + 개발용 OOD 종류마다 5장(55)
  + dev 100종 소분류마다 1장(100). 무작위는 고정 시드 20261117이라 매 회차 같은 문서다.
  OOD는 규칙 1·4가 「기타」 판정을 느슨하게 만드는 부작용을 감시하려고 꼭 넣는다.
- 반복 표본의 한계: dev는 소분류당 1장이라 다른 소분류로의 회귀를 놓칠 수 있다(신뢰구간이 넓다). 그래서 마지막 전체 측정에서
  dev 전부(극비 dev 전부 포함)를 다시 확인한다.
- 결과에는 세트별 표본 크기와 정답률의 95% 신뢰구간(Clopper-Pearson)을 같이 적는다. 표본 정확도는 전체 정확도의 추정치다.
- 마지막 1회: 전체(극비 dev 전부 포함).
- 멈춤 조건: 회귀셋에서 새로 틀린 문서가 고친 문서보다 많거나, 극비 문서가 다른 코드·「기타」로 바뀌거나, 개선이 멈출 때.
- 명령은 `src/engine/tune_set.py` 머리말. 채점: `python -m src.engine.tune_set score results/<실행1> results/<실행2>`.
