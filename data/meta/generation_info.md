# 합성 문서 데이터셋 생성 명세 (LLM & Prompt 기록)

## 1. 생성 모델 및 파이프라인
- 데이터 합성 LLM: Gemini 2.5 Pro / Claude 3.5 Sonnet (한국어 기업 문서 HTML/JSON 템플릿 설계 및 Rule-based 데이터 증량)
- 렌더링 도구: Playwright (Chromium Headless) A4 PDF 렌더링 후 PyMuPDF (fitz) 200 DPI PNG 변환 (다중 페이지는 _p1.png, _p2.png 분할)
- 하드셋 변형: `src/eval/augment.py`가 깨끗한 이미지 전부를 순서대로(순차 처리, 시드 42) 4종 변형 — ① 스캔 기울어짐(±1.8~2.5° 회전 + 약한 블러) ② 저화질 스캔(대비 85% + 가우시안 노이즈) ③ 초점 흐림(블러 + 밝기 90%) ④ 스마트폰 촬영(±1.5° 회전 + 가로 조명 그라데이션)
  - ponytail: 병렬 처리 없음; 1,264장 기준 수 분 내 완료. 데이터가 늘어 생성 시간이 문제가 되면 `multiprocessing.Pool` 도입

## 2. 데이터 생성 프롬프트 (Generation Prompt)
당신은 대한민국 기업(기준 회사명: (주)에이치에스리테일 / HS리테일)의 인사·재무·경영·영업·고객·법무 부서 문서를 작성하는 데이터 생성 전문가입니다.
주어진 양식 스키마(JSON/HTML 템플릿)에 맞추어 실제 기업에서 사용하는 것처럼 자연스럽고 사실적인 한국어 비즈니스 문서 데이터를 생성하세요.
1. 중심 기업명은 '(주)에이치에스리테일(HS리테일)'을 기본 당사자로 설정하고, 상대 거래처명·담당자명·금액·날짜·품목은 매 문서마다 서로 다르게 다양화할 것.
2. 재무제표의 차변/대변 합계 및 당기순이익 산출 등 회계 항등식이 수학적으로 일치하도록 구성할 것.
3. 법무/계약 문서는 실제 대한민국 표준계약서 조항 체계와 용어를 준수할 것.
4. OOD(분류 체계 외) 문서는 사내 일반 행정 문서 3종(법인카드지출결의서, 주간업무회의록, 부서간업무협조전)에 대해 각각 20건씩(총 60건) HS리테일 명의로 생성할 것.

## 3. OOD셋 생성 방식 (2026-10-05 재생성)
- `src/eval/render_ood.py`가 규칙 기반으로 만든다 (LLM 미사용, 시드 42라 다시 실행해도 같은 결과).
- 3종은 양식이 서로 다르다: 법인카드지출결의서(결재란·카드 사용 내역 표), 주간업무회의록(회의 개요·안건별 결정 사항·할 일 표), 부서간업무협조전(수신·발신·참조, 요청 본문, 회신란).
- 회사명은 본 데이터와 같은 '(주)에이치에스리테일'이고, 문서번호는 `HS-재무-2026-0001` 같은 사내 번호를 쓴다.
- 문서 안에 'OOD', '분류 체계 외' 같은 정답 단서를 넣지 않는다. 이전 버전은 문서번호(`OOD-03-2026-007`)·비고 칸·회사명 표기(에이지에스)로 정답이 드러나 다시 만들었다.
- 렌더링: Playwright로 A4(794×1123 CSS px)를 배율 2.09로 캡처해 본 데이터와 같은 1656×2342 PNG로 저장.

## 4. 새 개발용 OOD (2026-10-29, `--dev2`)
- `python src/eval/render_ood.py --dev2` → `data/images/ood_dev2/` 60장, `data/meta/ood_dev2_labels.csv` (DEVOOD-07~12, 종류당 10건, 시드 11).
- 사내 미등록 3종(시설점검일지, 고객사과문발송대장, 반품폐기확인서)과 사외 3종(제과레시피카드, 악보, 택배운송장). 사외 문서에는 회사명·결재란을 넣지 않았고 라벨의 `company`는 '사외'다.
- 승격 6종(발주서 등)이 소분류가 되면 DEVOOD-03(발주서)이 「기타」 정답에서 빠지므로 그 대신 확신도·「기타」 시험에 쓴다. 기존 개발용(DEVOOD-01~06)·최종(OOD-01~03)과 폴더·라벨·코드·시드를 따로 둔다.
- 문서 안에 '지출결의서'·'활동보고서'·'출장정산서'나 'OOD'·'분류 체계 외' 같은 낱말을 쓰지 않는다. A4 한 장을 넘치면 생성이 멈춘다(`strict`).
- 택배운송장은 실제로는 소형 스티커라 A4 윗부분에 한 장을 놓았다. 악보는 가상의 곡(음표 무작위)이다.
- 평가는 `python -m src.engine.run --images data/images/ood_dev2 --labels data/meta/ood_dev2_labels.csv --split ood` (API 키 필요, 아직 미실행).
- 29종 체계 기준 합본(DEVOOD-03 발주서 제외, 11종 110장): `python src/eval/merge_ood_dev.py` → `data/meta/ood_dev_all_labels.csv`. 판단 근거는 `docs/ood_dev_all_notes.md`.
