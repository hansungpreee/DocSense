# DocSense 업로드 검사 확장 (시연용 시제품)

ChatGPT(chatgpt.com)에 파일을 올리기 전에 로컬 검사 서버(`src/api/server.py`)로 보안 등급을 확인한다.
실제 전송 차단 장치가 아니라 시연용 경고다. 텍스트·클립보드 붙여넣기, 다른 사이트·브라우저는 검사하지 않는다.

## 등급별 동작

| 서버 판정 (`handling_grade`) | 동작 |
|---|---|
| 기밀 | 빨간 경고. 「책임자 승인」 체크 후에만 「그래도 업로드」, 기본은 취소 |
| 대외비, 「기타」, 미산정, 합산 미확정 | 경고와 업로드/취소 확인 창 (기본 취소) |
| 사내한정, 공개 | 오른쪽 아래에 등급만 3초 표시하고 통과 |
| 검사 실패 (서버 꺼짐, 60초 초과, API 오류, PNG·JPG·PDF·DOC·DOCX 아닌 형식, 20MB 초과) | 「검사하지 못했습니다」 확인 창 (기본 취소) |

판단과 사용자 선택은 `logs/gate.log`에 한 줄씩 남는다 (문서 내용은 남기지 않음).

## 같은 파일 재검사 (결과 재사용)

실제 API 모드에서 한 번 확정된 파일은 다시 올릴 때 모델을 부르지 않고 저장된 소분류를 쓴다. 등급과 동작은 매번 현재 등급표로 다시 정한다.

- 저장 위치 `logs/check_cache.json` (커밋 안 함). 저장 항목은 키(원본 바이트 SHA-256 + 검사 설정), 소분류 코드, 모델, 프롬프트 버전, 검사 시각뿐이다. 원본·본문·파일명·등급·사용자 선택은 저장하지 않는다.
- 모델(`VLM_MODEL`), 프롬프트 버전(`PROMPT_VERSION`), 분류 체계 파일 내용이 바뀌면 키가 달라져 자동으로 다시 검사한다. 그 밖의 검사 방식(PDF 변환 등)을 바꾸면 `server.py`의 `CACHE_VERSION`을 올린다.
- 검사 실패, 「기타」, 합산 미확정은 저장하지 않고 매번 다시 검사한다. 파일을 한 글자라도 고치면 새 파일로 본다.
- 확장 화면에 「기존 검사 결과 사용」이 표시되고, `gate.log` check 줄 끝에 `cached`/`new`와 걸린 시간(ms)이 남는다.
- MOCK 모드와 `--no-cache`로 켠 서버에서는 쓰지 않는다. 비우려면 서버를 끄고 `logs/check_cache.json`을 지운다.

## 실행 (저장소 루트에서, 한 줄씩)

1. 검사 서버 켜기. `.env`의 `DEMO_MOCK`이 0이 아니면 API 없이 파일명 앞 코드로 가짜 분류한다.

```
python -m src.api.server
```

등급표 `config/security_grades.yaml`이 아직 없으면 모든 문서가 대외비 경고로 나온다. 초안으로 리허설하려면:

```
python -m src.api.server --grades security_grades_draft_4level.yaml
```

2. 크롬 주소창에 `chrome://extensions` → 오른쪽 위 「개발자 모드」 켜기 → 「압축해제된 확장 프로그램을 로드합니다」 → 저장소의 `extension` 폴더 선택.
3. chatgpt.com을 새로 고침한 뒤 파일을 올린다. 확장을 고친 뒤에는 확장 카드의 새로 고침 버튼과 chatgpt.com 새로 고침을 둘 다 한다.

서버 확인:

```
curl http://127.0.0.1:8765/health
```

## 수동 점검표 (시연 전, MOCK + 등급표 초안)

파일명은 `app/mock/`처럼 코드로 시작하면 그 소분류로 분류된다 (예: `FIN-03_손익계산서.png`).

- [ ] 기밀 (`FIN-03_*.png`) 파일 선택 → 빨간 창, 체크 전 업로드 버튼 비활성, 취소하면 첨부 안 됨
- [ ] 기밀 체크 후 업로드 → ChatGPT 입력창에 첨부됨
- [ ] 대외비 (`HR-01_*.png`) → 확인 창, 업로드 누르면 첨부됨
- [ ] 사내한정·공개 → 오른쪽 아래 표시만 나오고 바로 첨부됨
- [ ] 체계 밖 (`회식사진.png`) → 「기타」, 근거 「분류 체계 밖 문서, 담당자 확인 필요」
- [ ] `*_lowconf.png` → 「(잠정)」 표시, 대외비 확인 창
- [ ] 드래그 놓기로 위 경우 중 2개 반복
- [ ] 여러 파일 한 번에 → 파일마다 따로 묻고 허용한 것만 첨부됨
- [ ] 서버 끄고 올리기 → 「검사 서버에 연결하지 못했습니다」
- [ ] `.docx` → 「검사할 수 없는 형식」
- [ ] `logs/gate.log`에 check·decision 줄이 남음
- [ ] Esc = 취소, Tab으로 창 안에서만 초점 이동

## 실패 경로·선업로드 확인 (실제 API 모드, 개발자도구)

검사가 끝나 업로드를 고르기 전에는 원본 파일이 ChatGPT로 나가지 않아야 한다. 파일 선택과 드래그 놓기 각각 확인한다.

1. chatgpt.com에서 F12 → 「Network」 탭 → 「Preserve log」 체크 → 필터 칸에 `file` 입력
2. 파일을 올리고 「검사 중」 창이 떠 있는 동안 목록에 새 업로드 요청(파일 크기만 한 요청, 이름에 `files`·`upload`)이 생기지 않는지 본다
3. 확인 창에서 「취소」 → 업로드 요청이 끝까지 없어야 한다. 「그래도 업로드」 → 그때 처음 생겨야 한다
4. 서버를 끈 채 올리기 → 「검사 서버에 연결하지 못했습니다」, 취소가 기본, 업로드 요청 없음
5. 체계 밖 파일 → 「기타」 확인 창, 자동 통과 없음
6. 시간 초과는 확장이 60초에 끊는다 (서버를 켠 채 응답이 늦을 때 「검사 시간이 60초를 넘었습니다」)

확인한 두 경로(파일 선택·드래그)만 보고한다. 붙여넣기 등 다른 경로까지 막았다고 말하지 않는다.

## 알려진 한계

- ChatGPT 화면 구조가 바뀌어 파일을 다른 경로로 받으면 검사되지 않을 수 있다. 시연 직전에 위 점검표를 다시 돈다.
- 검사 서버는 한 번에 한 파일씩 처리한다. 실제 API 모드에서 처음 보는 파일은 1건당 10~20초 걸린다 (재검사는 위 결과 재사용).
- 검사 대상 문서는 Qwen API(외부)로 보내 분류한다. 외부 전송 자체를 막는 구조가 아니다.
- 실제 모드는 Qwen·Gemini를 동시에 불러 합산 확정한다(데모와 같은 규칙, 11/17). `.env`에 `GEMINI_API_KEY`가 없으면 모든 결과가 미확정이라 최소 대외비 확인 창이 뜬다. Gemini 호출이 더해져 검사가 느려질 수 있다(두 모델 중 느린 쪽, 최대 60초).
